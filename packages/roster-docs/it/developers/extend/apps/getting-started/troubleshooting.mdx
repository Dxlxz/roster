## Problemi comuni

* **Errori dell'ambiente locale**, controlla `roster local status` e `roster local logs --no-follow`. Docker deve essere installato e in esecuzione con un contesto socket locale. Aggiungi `--test` per l'istanza di test. Un avvio non riuscito conserva il relativo container e i dati per la diagnosi.
* **Versione di Node errata** — È necessaria la versione 24.5+ o 26.5+ (`engines.node: ^24.5.0 || ^26.5.1`). Verifica con `node -v`.
* **Yarn 4 mancante** — Esegui `corepack enable` (su Node 26, prima `npm install -g corepack`).
* **Dipendenze danneggiate** — `rm -rf node_modules && yarn install`.
* **`yarn.lock` vuoto** — La build non riesce e mostra "yarn.lock is empty" quando il file di lock esiste ma non contiene alcun contenuto; esegui `yarn install` per rigenerarlo.
* **Errori di `roster-sdk` dopo l'aggiornamento alla v2.8.0** — è stato spostato da `dependencies` a `devDependencies` nella v2.8.0. Vedi [Struttura del progetto → Dipendenze](/it/developers/extend/apps/getting-started/project-structure#dependencies).
* **`roster app build` mostra un avviso su `roster-client-sdk` sotto `dependencies`** — viene fornito in fase di esecuzione da roster, quindi dovrebbe essere spostato in `devDependencies` insieme a `roster-sdk`. Vedi [Struttura del progetto → Dipendenze](/it/developers/extend/apps/getting-started/project-structure#dependencies).
