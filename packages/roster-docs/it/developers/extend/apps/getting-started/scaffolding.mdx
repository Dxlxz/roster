## Panoramica

Utilizza la CLI standalone per generare un oggetto, un campo, una regola di convalida, una funzione logica o un componente front-end:

```bash
roster app add
roster app add object --name invoice --name-plural invoices --no-input
roster app add field --name amount --type NUMBER --object <object-uuid> --no-input
roster app add validation-rule --name invoice-has-amount --object <object-uuid> --no-input
roster app add logic-function --name send-invoice --no-input
roster app add front-component --name invoice-panel --no-input
```

Senza flag, i terminali interattivi richiedono i valori mancanti. Per script e agenti, fornisci i campi obbligatori e usa `--no-input` o `--json`.

La generazione di oggetti può anche creare una vista, un elemento di navigazione e il layout della pagina del record:

```bash
roster app add object --name invoice --name-plural invoices \
  --create-view --create-navigation-menu-item --create-page-layout --no-input
```

Per altri tipi di entità, scrivi il file `define*` corrispondente usando `roster-sdk/define` e un UUID v4 valido. Esegui `roster app typecheck` e `roster app plan` prima della sincronizzazione.

`--path` seleziona la directory dell'app, non una cartella di output personalizzata. Esegui `roster app add --help` per le opzioni supportate.
