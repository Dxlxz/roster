Le CLI `yarn roster` est votre interface pour tout ce qui concerne les applications. Liste complète des commandes :

| Commande                                        | Ce que cela fait                                                                          | Documenté dans                                                                                                  |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `dev`                                           | Surveille les fichiers sources et synchronise en direct les modifications                 | [Prise en main rapide](/fr/developers/extend/apps/getting-started/quick-start)                                     |
| `plan`                                          | Prévisualiser les modifications de métadonnées sans les appliquer                         | [Synchronisation et récupération](/fr/developers/extend/apps/operations/sync-and-recovery#previewing-changes-plan) |
| `appliquer`                                     | Appliquer les modifications de métadonnées après avoir affiché le plan                    | [Synchronisation et récupération](/fr/developers/extend/apps/operations/sync-and-recovery)                         |
| `dev:build`                                     | Compiler l’application et générer le client d’API (`--tarball` pour empaqueter un `.tgz`) | [Publication](/fr/developers/extend/apps/operations/publishing)                                                    |
| `dev:typecheck`                                 | Exécuter la vérification des types TypeScript                                             | [Tests](/fr/developers/extend/apps/operations/testing)                                                             |
| `dev:add`                                       | Générer la structure d’une nouvelle entité                                                | [Génération de structure](/fr/developers/extend/apps/getting-started/scaffolding)                                  |

Chaque commande accepte `-r, --remote \<name>` pour cibler un serveur distant spécifique au lieu de celui par défaut.

## Exécuter des fonctions (`yarn roster dev:function:exec`)

Exécutez une fonction logique manuellement sans la déclencher via HTTP, cron ou un événement de base de données :

```bash filename="Terminal"
# Execute by function name
yarn roster dev:function:exec -n create-new-post-card

# Execute by universalIdentifier
yarn roster dev:function:exec -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf

# Pass a JSON payload
yarn roster dev:function:exec -n create-new-post-card -p '{"name": "Hello"}'

# Execute the install and uninstall hooks
yarn roster dev:function:exec --postInstall
yarn roster dev:function:exec --preInstall
yarn roster dev:function:exec --uninstall
```

## Afficher les journaux des fonctions (`yarn roster dev:function:logs`)

Diffuser en continu les journaux d'exécution des fonctions logiques de votre application :

```bash filename="Terminal"
# Stream all function logs
yarn roster dev:function:logs

# Filter by function name
yarn roster dev:function:logs -n create-new-post-card

# Filter by universalIdentifier
yarn roster dev:function:logs -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf
```

<Note>
Ceci est différent de `yarn roster docker:logs`, qui affiche les journaux du conteneur Docker. `yarn roster dev:function:logs` affiche les journaux d'exécution des fonctions de votre application depuis le serveur roster.
</Note>

## Génération du client typé (`yarn roster dev:generate-client`)

Régénérez le client API typé (`roster-client-sdk`) à partir du schéma du remote actif, sans compiler ni synchroniser une application. Utilisez-le pour obtenir un client typé dans n’importe quel projet — comme un service back-end hébergé dans un dépôt distinct — qui communique avec votre instance roster :

```bash filename="Terminal"
# In your project (no roster app definition required)
yarn add roster-sdk roster-client-sdk

# Connect to the roster instance to generate the client from
yarn roster remote:add

# Generate the typed client into node_modules/roster-client-sdk
yarn roster dev:generate-client
```

Puis importez le client dans votre code :

```typescript
import { CoreApiClient } from 'roster-client-sdk/core';
```

Relancez la commande chaque fois que votre modèle de données change afin d’actualiser les types générés.

<Note>
Le client est généré dans `node_modules`, il n’est donc pas versionné avec votre code. Exécutez `yarn roster dev:generate-client` après chaque installation (par exemple dans un script `postinstall` ou dans un pipeline CI).
</Note>

## Désinstaller une application (`yarn roster app:uninstall`)

Supprimez votre application de l'espace de travail actif :

```bash filename="Terminal"
yarn roster app:uninstall

# Skip the confirmation prompt
yarn roster app:uninstall --yes
```

## Gestion des remotes

Un remote est un serveur roster auquel votre application se connecte. Lors de la configuration, le générateur en crée un automatiquement pour vous. Vous pouvez ajouter d’autres remotes ou basculer entre eux à tout moment.

```bash filename="Terminal"
# Add a new remote (opens a browser for OAuth login)
yarn roster remote:add

# Connect to a local roster server (auto-detects port 2020 or 3000)
yarn roster remote:add --local

# Add a remote non-interactively (useful for CI)
yarn roster remote:add --url https://your-roster-server.com --api-key $roster_API_KEY --as my-remote

# List all configured remotes
yarn roster remote:list

# Set the active remote
yarn roster remote:use <name>

# Check that the active remote's authentication is still valid
yarn roster remote:status

# Remove a remote
yarn roster remote:remove <name>
```

Vos identifiants sont stockés dans `~/.roster/config.json`.
