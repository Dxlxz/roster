## Rularea CLI-ului

CLI-ul `roster` se conectează la spațiile de lucru roster din terminalul dvs. Folosiți-l pentru a inspecta metadatele, a citi înregistrări, a trimite solicitări API și a crea, sincroniza și depana aplicații. CLI-ul însuși necesită **Node.js 24.5+**. Dezvoltarea aplicațiilor necesită, de asemenea, o versiune Node acceptată de SDK-ul instalat; consultați [Pornire rapidă](/ro/developers/extend/apps/getting-started/quick-start#before-you-start).

Rulați orice comandă prin `npx`, fără o instalare globală:

```bash filename="Terminal"
npx roster@latest --version
```

Sau instalați-l o singură dată la nivel global și apelați `roster` direct:

```bash filename="Terminal"
npm install -g roster
roster --version
```

Exemplele de mai jos folosesc `roster`. Înlocuiți `roster` cu `npx roster@latest` dacă nu l-ați instalat global. Rulați `roster commands` pentru lista completă de comenzi și `roster \<command> --help` pentru opțiunile unei comenzi.

| Comandă         | Ce face                                                                                |
| --------------- | -------------------------------------------------------------------------------------- |
| `autentificare` | Autentificați-vă, verificați și eliminați acreditările                                 |
| `remote`        | Enumerați, selectați, redenumiți și eliminați conexiunile salvate la spațiile de lucru |
| `metadate`      | Inspectați obiecte și câmpuri                                                          |
| `data`          | Listează, citește și exportă înregistrări                                              |
| `api`           | Trimiteți cereri REST sau GraphQL brute                                                |
| `open`          | Deschideți spațiul de lucru în browser                                                 |
| `aplicație`     | Creați, compilați, sincronizați, depanați și dezinstalați aplicații                    |
| `local`         | Începeți, inspectați, opriți, actualizați și resetați mediul de dezvoltare locală      |
| `doctor`        | Diagnosticați CLI-ul, SDK-ul aplicației și conexiunea la spațiul de lucru              |

Fiecare comandă care comunică cu un spațiu de lucru acceptă `--remote \<name>` pentru a viza o conexiune salvată alta decât cea implicită și `--json` pentru ieșire structurată.

## Conectarea la un spațiu de lucru

Autentificați-vă cu browserul. `--use` face din această conexiune conexiunea implicită:

```bash filename="Terminal"
roster auth login --url https://acme.roster.dev --use
roster auth status
```

Utilizați adresa spațiului dvs. de lucru sau adresa serverului pentru o configurare locală: `http://localhost:2020` pentru [mediul de dezvoltare local](/ro/developers/extend/apps/getting-started/local-server), `http://localhost:3000` pentru o copie locală a codului sursă. Puteți copia comanda exactă din **Settings > Developers > CLI**. Autentificarea prin browser necesită roster 2.42 sau o versiune ulterioară.

Păstrați mai multe conexiuni denumindu-le:

```bash filename="Terminal"
roster auth login --url http://localhost:2020 --name local
roster remote list
roster remote use local
```

În CI sau scripturi, redirecționați o cheie API în loc să vă autentificați cu browserul:

```bash filename="Terminal"
printf '%s' "$roster_API_KEY" | roster auth login --with-token --url https://acme.roster.dev --name ci
```

De asemenea, puteți seta `roster_API_URL` și `roster_API_KEY` pentru o singură rulare fără a salva nimic. Conexiunile salvate se află în `~/.roster/config.json`.

Comenzile selectează un spațiu de lucru în această ordine:

1. Un `--remote \<name>` explicit, care suprascrie variabilele de mediu țintă.
2. `roster_REMOTE` sau perechea `roster_API_URL` și `roster_API_KEY`. Nu combinați aceste două metode.
3. Remote-ul implicit salvat.

`auth login --name \<name>` salvează o conexiune, dar păstrează un remote implicit existent. Adăugați `--use` sau rulați `roster remote use \<name>` pentru a schimba remote-ul implicit.

### În spatele unui proxy de autentificare

Dacă un proxy cu recunoaștere a identității, cum ar fi Cloudflare Access, Google IAP, Pomerium sau oauth2-proxy, se află în fața serverului, comenzile eșuează cu `PROXY_AUTH_REQUIRED`. Furnizați CLI-ului acreditările proxy-ului ca antete. Utilizați o comandă care afișează unele noi sau valori fixe pentru un token de serviciu:

```bash filename="Terminal"
roster auth login --url https://roster.example.com \
  --proxy-header-command 'echo "cf-access-token: $(cloudflared access token -app=https://roster.example.com)"'

roster auth login --url https://roster.example.com \
  --proxy-header "CF-Access-Client-Id: $CLIENT_ID" \
  --proxy-header "CF-Access-Client-Secret: $CLIENT_SECRET"
```

Ambele sunt salvate în conexiune. Comanda afișează câte un rând `Name: value` pentru fiecare antet. CLI-ul o rulează din nou când proxy-ul respinge anteturile, iar `PROXY_HEADERS_FAILED` raportează o comandă care eșuează. În CI, setați în schimb `roster_PROXY_HEADERS` (câte un `Name: value` pe rând) sau `roster_PROXY_HEADER_COMMAND`. Anteturile proxy sunt trimise doar la URL-ul API al conexiunii și nu pot înlocui `Authorization`. Consultați [referința CLI](https://github.com/Dxlxz/roster/blob/main/packages/roster-cli/docs/commands.md#authenticating-proxies) pentru fiecare opțiune.

## Explorarea datelor

```bash filename="Terminal"
# Objects and fields
roster metadata object list
roster metadata field list companies

# Records
roster data list companies --limit 5
roster data list companies --filter 'employees[gte]:5000' --order-by 'employees[DescNullsLast]'
roster data get people <id>

# Raw API requests
roster api rest '/rest/companies?limit=5'
roster api graphql --query '{ companies(first: 2) { edges { node { name } } } }'

# Open the workspace, or a page inside it
roster open
roster open settings/developers
```

Numele obiectelor sunt nume API exacte, la singular sau plural (`company` sau `companies`). Scrierile API brute se execută fără un pas de confirmare, iar permisiunile din spațiul de lucru se aplică în continuare.

## Construirea unei aplicații

```bash filename="Terminal"
npx roster@latest app init my-app
cd my-app
yarn install
npx roster@latest app apply --create
npx roster@latest app dev
```

* `app init` scrie un proiect nou din șablon. Nu instalează dependențe și nu contactează un spațiu de lucru.
* `app apply --create` compilează aplicația, o înregistrează în spațiul de lucru, o instalează și îi sincronizează metadatele.
* `app dev` monitorizează sursa și sincronizează fiecare compilare reușită.

Fișierele locale externe existente utilizează evenimente native ale sistemului de fișiere. Căile lipsă sau șterse utilizează verificări de recuperare o dată pe secundă până când monitorizarea nativă poate fi reluată. Rădăcinile directoarelor home și temporare, precum și directoarele lor părinte, sunt excluse din observarea automată a directoarelor externe. Dacă `WATCH_SCOPE_LIMITED` apare pentru un import lipsă, corectează importul, apoi editează un fișier al aplicației sau repornește `app dev`.

Rulați `roster app dev --verbose` pentru a vedea căile monitorizate și excluse după prima încercare de compilare și ori de câte ori acestea se modifică. Adăugați `--format ndjson` pentru evenimente de progres structurate `watch-scope`.

Alte comenzi pentru aplicații:

| Comandă                       | Ce face                                                                                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app add`                     | Generează structura unui obiect, câmp, funcții logice sau alte entități                                                                                         |
| `app build` / `app typecheck` | Compilați sau verificați tipurile aplicației local                                                                                                              |
| `app plan`                    | Previzualizați modificările de metadate pe care le-ar face o aplicare                                                                                           |
| `app apply`                   | Compilați, încărcați și sincronizați aplicația                                                                                                                  |
| `app generate-client`         | Regenerați clientul API tipizat fără sincronizare                                                                                                               |
| `app pull`                    | Restaurează metadatele, traducerile, dependențele, resursele publice și sursa funcțiilor de componente și de logică acceptate, cu importuri locale inventariate |
| `app translations extract`    | Extrage șirurile traducibile în cataloagele din `locales/`                                                                                                      |
| `app publish`                 | Publicați aplicația pe npm sau într-un registru privat roster                                                                                                   |
| `app install`                 | Instalați în spațiul de lucru un pachet de aplicație deja înregistrat                                                                                           |
| `app uninstall`               | Eliminați aplicația și tot ce îi aparține din spațiul de lucru                                                                                                  |

Definițiile care lipsesc din sursă sunt șterse implicit din spațiul de lucru. Transmiteți `--no-prune` pentru a le păstra. Aplicația Personalizată pentru spațiul de lucru le păstrează dacă nu transmiteți `--prune`. Ștergerea obiectelor sau a câmpurilor șterge și datele acestora, deci necesită confirmare. Consultați [Sincronizare și recuperare](/ro/developers/extend/apps/operations/sync-and-recovery) pentru detalii.

## Executarea funcțiilor

Rulați o funcție logică implementată fără a o declanșa printr-o rută, un cron sau un eveniment de bază de date. Sincronizați mai întâi modificările locale cu `app apply` sau `app dev`.

```bash filename="Terminal"
roster app exec --name create-new-post-card
roster app exec --name create-new-post-card --payload '{"name": "Hello"}'

# Install and uninstall hooks
roster app exec --post-install
roster app exec --pre-install
roster app exec --uninstall-hook
```

Executarea funcțiilor necesită autentificare prin browser. Cheile API nu le pot executa.

## Monitorizarea jurnalelor funcțiilor

Transmiteți în flux ieșirea funcțiilor logice ale aplicației pe măsură ce execuțiile se finalizează:

```bash filename="Terminal"
roster app logs
roster app logs --name create-new-post-card
```

Afișează doar execuțiile noi, nu și pe cele anterioare.

## Dezinstalarea unei aplicații

```bash filename="Terminal"
roster app uninstall
roster app uninstall --yes
```

Aceasta execută cârligul de dezinstalare al aplicației și șterge tot ce îi aparține, inclusiv obiectele, câmpurile și datele lor. Aplicația rămâne înregistrată, astfel încât `roster app apply` o poate instala din nou.

## Diagnosticarea problemelor

```bash filename="Terminal"
roster doctor
roster doctor --offline
```

`doctor` verifică versiunea Node, ce binar `roster` se află în `PATH`, conexiunile salvate și SDK-ul aplicației, apoi raportează ce trebuie remediat.

## Scripturi și teste

Rezultatul compilării aparține CLI-ului. Nu citiți `.roster/output/manifest.json` și nu importați cod intern de compilare; citiți `data.manifest` din `roster app build --json`.

## Exportă înregistrările spațiului de lucru

```bash
roster data export companies --output companies.csv
roster data export companies --fields name,domainName,employees --filter 'employees[gte]:5000' --output large-companies.csv
```

`data export` necesită permisiunea **Export CSV** a spațiului de lucru. Urmărește progresul exportului pe server, apoi transmite CSV-ul către `--output`. Permisiunile pentru înregistrări și câmpuri sunt aplicate de server. Nu este necesar un proiect de aplicație; selectează o conexiune salvată cu `--remote` sau folosește acreditările obișnuite din mediu.

Fișierul de ieșire apare numai după o descărcare reușită. Fișierele existente sunt păstrate, cu excepția cazului în care transmiți `--force`. Descărcările sunt limitate la 1 GiB și 15 minute. Dacă este întrerupt, rulează din nou exportul; linkul de descărcare nu poate fi reutilizat. `--json` raportează ID-ul exportului, calea, dimensiunea și durata; `--format ndjson` transmite și progresul. CSV-ul însuși este scris numai în fișierul specificat.
